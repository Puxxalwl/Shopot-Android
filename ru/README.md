# Stille Messenger (Android)

**English** | [Русский](ru/README.md)

Android-клиент для демона [stille-messenger-core](https://github.com/puxxalwl/stille-messenger-core).

## Возможности
- **P2P — без серверов** — прямой TCP (порты 7777–7786), LAN discovery или self-hosted relay
- **Сквозное шифрование (E2EE)** — клиент никогда не работает с ключами
- **Без телеметрии, аналитики, Firebase**
- **Glassmorphism UI** — iPhone-стиль с размытием фона
- **Богатые сообщения** — bold, italic, spoiler, code, links
- **Реакции** — любой Unicode эмодзи
- **Файлы и фото** — до 64 МБ
- **Голосовые звонки** — 16 кГц E2EE, ADPCM + DTX
- **Офлайн-доставка** — зашифрованный outbox с ACK и dedup
- **Восстановление аккаунта** — passkey + один запечатанный ядром файл в
  собственном облаке (Google Диск, Яндекс Диск или любой WebDAV-сервер)
  восстанавливают личность, профиль, контакты и маршруты на новом устройстве;
  история сообщений не синхронизируется. См. [ru/RECOVERY.md](ru/RECOVERY.md).

## Первый запуск

При первом запуске Stille Messenger показывает локальное окно настройки: язык
интерфейса, системная/светлая/тёмная тема и имя, отображаемое в профиле.
Выборы хранятся на устройстве и доступны для изменения позже в приложении. Stille
может один раз за запуск проверить публичные GitHub Releases; проверку можно
отключить в настройках, а ручная проверка остаётся в разделе «О Stille».
Обновления скачиваются только после подтверждения и проверяются (контрольная
сумма, подпись, версия) перед автоматическим запуском системного установщика
Android — разрешение «установка из неизвестных источников» запрашивается до
загрузки, а не после неё.


Stille — «тишина» по-немецки. Имя ограничено 1–32 байтами UTF-8, как в ядре
(16 русских букв или 8 четырёхбайтовых emoji). Кнопка «Продолжить» находится
внизу, форма прокручивается. Android application ID изменён на `com.stille.messenger`: отдельная установка без автоматического переноса старых данных.

## Навигация

Переключайте Профиль, Чаты, Контакты и Настройки горизонтальными свайпами или
нижними вкладками. Переходы используют плавный сдвиг с лёгкой имитацией motion
blur на Android 12+; на старых устройствах — сдвиг, масштабирование и затухание
без blur. В покое содержимое чёткое. В разговоре и листе приглашений свайпы
разделов отключены. «Назад» из разговора возвращает в исходный раздел.

## Фото профиля

В профиле нажмите **Установить фото** / **Изменить фото**. Системный выборщик не
требует общего доступа к хранилищу. Изображения до 8 МиБ обрабатываются вне UI:
учёт EXIF-ориентации, квадратная обрезка по центру, JPEG без метаданных,
уменьшение и сжатие до лимита ядра 16 000 байт. Успех показывается только после
подтверждения id содержимого и размера через SET_AVATAR. При ошибке остаётся
прежнее фото.

Профиль, чаты и контакты показывают фото из памяти, при отсутствии — инициалы.
Кеш ограничен 20 изображениями, включая своё; фото собеседника требует
подтверждённого JOIN. Ядро хранит загруженное фото зашифрованно между запусками.
**Ограничение текущего API:** метода чтения байтов собственного фото нет,
поэтому свой предпросмотр доступен только пока его хранит процесс сервиса.
Фото собеседников приходят через AVATAR_RECEIVED; клиент не опрашивает ядро
и не пишет незашифрованный кеш. Съёмка камерой, ручной редактор обрезки и
API удаления фото не реализованы.

## Приглашения и сканирование QR в реальном времени

Откройте **Добавить контакт** в разделах «Чаты» или «Контакты». Владелец
приглашения показывает одноразовый QR/ссылку; второе устройство может нажать
**Сканировать камерой** для декодирования QR прямо из видеопотока или выбрать
сохранённое изображение. Кадры обрабатываются одним ограниченным worker-ом,
не логируются и не записываются на диск; камера освобождается при закрытии
сканера или паузе приложения. После `ACCEPT_INVITE` интерфейс ждёт
аутентифицированное событие `CONTACT_JOINED`; одновременное принятие одного
одноразового кода сериализуется ядром, и только первый валидный JOIN создаёт
соединение. Для ссылки без адреса устройства должны быть в одной LAN с
разрешённым multicast либо нужно использовать доступный адрес/relay.
После `ACCEPT_INVITE` возвращённый ядром cid считается ожидающим до
аутентифицированного presence/JOIN; поэтому при гонке двух устройств UI не
доверяет предварительному имени. Цвета темы теперь плавно меняются сами,
переходы разделов и чата укорочены (вкладки — 200 мс). На Android 12+ возвращено
кешированное GPU-размытие из v0.2.2; на старых устройствах — slide/scale/fade.

## Постоянная ссылка-приглашение

Помимо одноразового приглашения, лист приглашений показывает **постоянную
ссылку** — `https://stille.im/invite/{код}` — которая является
персистентным кодом профиля (`CREATE_INVITE_EX` режим 4, API 2.8.0) без
префикса `stille://`. Ссылка **содержит полное приглашение сама**:
детерминированно выведена из сида личности, не «сгорает», не расходует
лимит четырёх одноразовых приглашений, и получивший её (мессенджер, QR,
тап) подключается напрямую — сайт stille.im служит только редиректором и
не хранит ни маппинга, ни короткого кода, ни bundle. **«Сбросить ссылку»**
ротирует секрет кода профиля (`REGENERATE_PROFILE_CODE`) при утечке:
ранее отправленные ссылки немедленно перестают действовать, существующие
контакты и чаты не затрагиваются.

Обрабатывает всё только приложение: переход по
`https://stille.im/invite/i/…` или `stille.im/invite/i3/…` (с префиксом
`https://` и без него; открытый `http://` отклоняется) восстанавливает код
локально, снова приставляя схему `stille://`, и сразу передаёт его в
`ACCEPT_INVITE` — без сетевых запросов и серверного состояния. Инвайт-коды
`stille://i…`, отправленные напрямую в мессенджере, открывают тот же
поток. Живой сканер камерой, выбор QR-изображения и вставка текста
принимают всё это через тот же парсер, а инвайт-коды никогда не
логируются.

## Сборка

```bash
# 1. Сборка stille-messenger-core для Android (требует Zig 0.17.0)
./tools/build-core.sh

# 2. Сборка Android-приложения
./gradlew :app:assembleDebug

# 3. Тесты
./gradlew :data:testDebugUnitTest :app:testDebugUnitTest

# Быстрая инкрементальная проверка Kotlin (сохраняет daemon Gradle/Kotlin)
./gradlew :app:compileDebugKotlin --daemon --offline --max-workers=2
```

**Требования:** Android 8.0+ (API 26), JDK 17, Zig 0.17.0 для сборки core.

## Подпись релизов и установка

Release-сборка текущей версии `3.1.1` (versionCode `30`) требует постоянный приватный keystore через `STILLE_KEYSTORE_PATH`,
`STILLE_STORE_PASSWORD`, `STILLE_KEY_ALIAS`, `STILLE_KEY_PASSWORD`. Debug-сборка
независима. Не коммитьте keystore и не выводите его содержимое в логи.

Для GitHub Actions нужны secrets `ANDROID_KEYSTORE_BASE64`, `ANDROID_STORE_PASSWORD`,
`ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD` и переменная репозитория
`ANDROID_SIGNING_CERT_SHA256` (SHA-256 публичного сертификата, 64 hex-символа).
Перед публикацией проверяются подпись, закреплённый сертификат, ZIP и выравнивание.
Без настройки релиз останавливается, а не подписывается случайным debug-ключом.

Опубликованные v0.2.3 и v0.2.4 подписаны разными временными ключами runner-а:
оба APK валидны, но Android не позволяет поставить один поверх другого.
Для обновления установленной версии нужен её исходный приватный ключ;
APK содержит только публичный сертификат. Не удаляйте приложение и не очищайте
данные ради проверки: можно потерять identity и историю. Новый постоянный ключ
решает совместимость будущих релизов, но не обновление старых установок.

Для защищённого локального ключа (`~/.local/share/stille-signing/release.p12`
и `release.password`, alias `stille-release`) используйте:

```bash
python3 tools/build-signed-release.py --offline
```

Права каталога — 700, файлов — 600. Храните защищённую резервную копию обоих
файлов вне репозитория. Скрипт не пересоздаёт отсутствующий ключ и отключает
configuration cache Gradle для подписи. Локальная сборка использует один worker,
heap Gradle 1536 МиБ и Kotlin внутри того же процесса вместо двух больших JVM.
Git-доступ по SSH не позволяет настроить
GitHub Actions secrets: для этого нужен доступ Secrets write к репозиторию.

## Linux-клиент

Официальный Linux-клиент — [EryyynIT/shopot](https://github.com/EryyynIT/shopot).
Он использует тот же stille-messenger-core и бинарный UDS API, поэтому служит
референсом desktop UX и интеграции.

## Архитектура

```
app/                      # Android-приложение: UI + foreground service
data/                     # Кодек бинарного протокола (соответствует CORE-API.md)
core-src/                 # Исходники stille-messenger-core (cloned)
tools/                    # Скрипты кросс-компиляции
```

`StilleService` — foreground service, который:
1. Использует `libstille.so` из установленного Android `nativeLibraryDir` (исполняемый файл, не JNI)
2. Один раз создаёт локальную identity через `stille-messenger-core init`, никогда не перезаписывая существующий seed (или стартует без профиля в recovery-режиме)
3. Запускает `stille-messenger-core serve` и подключается к UDS `$HOME/.stille-messenger/api.sock`
4. Отправляет `GET_VERSION` для проверки совместимости
5. Слушает события и рассылает их в UI через `StateFlow`

Если приглашения или фото профиля сообщают, что локальное ядро недоступно,
пересоберите APK после `bash ./tools/build-core.sh`. В APK должен быть
`lib/arm64-v8a/libstille.so`, создаваемый из
`app/src/main/jniLibs/arm64-v8a/libstille.so` (исключён из Git).
Включена распаковка native-файлов: Android 10+ запрещает исполнение из записываемой
папки приложения, поэтому копия assets в `filesDir` не подходит. Упаковка APK
завершается ошибкой при отсутствии AArch64-ядра; проверка только Kotlin не требует
бинарника. В профиле и приглашениях есть повторный запуск. Диагностика содержит
только фиксированные этапы и типы ошибок, без вывода ядра и идентификаторов.
Файл технического лога (этапы и типы ошибок; без сообщений, контактов и
секретов) можно поделиться из настроек, быстро нажав 5 раз на «О Stille».
Установите обновлённый APK поверх приложения; не очищайте данные ради исправления запуска.

## Добавление друга

Откройте приглашение из раздела «Чаты» или «Контакты». Stille создаёт одноразовый
код через бинарный API `CREATE_INVITE` и хранит его только в памяти. Ссылку можно
скопировать, отправить системным меню Android или показать чёрно-белым QR с
символом Stille без надписи. Получатель вставляет ссылку или выбирает изображение
QR; Stille принимает его через `ACCEPT_INVITE` и показывает контакт только после
доверенного события `CONTACT_JOINED`.

```
A: CREATE_INVITE → "stille://i/ABC123..."
   (делимся в любом мессенджере или через QR)
B: ACCEPT_INVITE → ждём CONTACT_JOINED → соединение установлено
```
